# ESSH v0.4.0 — persistent SSH workspace

The default interface now uses local and remote tmux to keep remote shells alive
across connection drops and local restarts. The previous interface remains available
through `essh legacy`.

## Highlights

- F2 cycles terminal, thin side health, half health, full health, and back to terminal.
- Full Linux health dashboard: network rates, CPU/core activity, memory, storage,
  peers and process tables, with thin meters matching the design reference.
- F1 help, F3 Sessions, F4 Main menu, F5/F6 switching, plus clickable session tabs
  and navigation controls.
- Host filtering, add/edit forms, independent SSH sessions, reconnect, and explicit
  confirmation before terminating a remote session.
- Offline hosts show unavailable telemetry and unverified remote state.
- Side health follows session changes; serialized pane updates prevent duplicate
  panes during fast navigation.

## Demo

The attached 38-second `essh-v3-demo.mp4` shows real SSH admin work with `df`, `lsblk`, `ps`,
`vmstat`, `ss` and `ip`, all health layouts, session navigation, help, and reconnect
with preserved remote shell state. Connection waits are shortened and key screens
pause for reading. `essh-v3-replay.html` is a standalone browser replay.

## Requirements

Local tmux 3.3+ and OpenSSH, with tmux installed on remote hosts. Detailed health
telemetry currently requires Linux. Initial samples may show unavailable values
until collection is ready.
