THE FLEET IS REAL, THE DISAGREEMENTS WERE STAGED
------------------------------------------------
The ten hosts are ten Debian containers (podman), each with its own hostname and
loopback address (127.0.0.11-20:2222) running a real sshd. essh connects over
russh with a real key; every metric, file listing and facet hash in these shots
was collected over that connection.

To give the divergence engine something to find, the fleet was made to disagree
the way a real one does:
  - edge-01  timezone set to Europe/Dublin, /etc/ssh/sshd_config hand-edited
  - db-02    a comment appended to /etc/nsswitch.conf
  - web-*    nginx installed (so listening ports differ from the rest)
  - cache-01 redis installed
Those are genuine differences between genuine hosts, deliberately created.

BUGS VISIBLE IN THESE SHOTS
---------------------------
- 11-forwards.png  Both forwards report "Active" but nothing is bound: no
  listener on 8080 or 15432 (`ss -ltn`), and curl to 127.0.0.1:8080 is refused
  while nginx answers 200 inside the container.
- 06-sessions.png  Session 1 — the only one opened with Enter from the dashboard
  instead of F9 — stayed on "Connecting" indefinitely with a blank pane and never
  collected facets. The eight opened with F9 connected in about a second.
- 02-dashboard.png  The role=web group row prints its consensus figure twice:
  "2 / 2 2 / 2 full consensus". The footer says "r probe", but `r` reloads the
  host list and discards live probe state — every host reads as unreachable
  until the next 60s probe cycle.
- 03-divergence.png  "1 peers never probed".
- 11-forwards.png  The add-forward format hint is clipped at the panel edge.
- 12-help.png      Help text wraps mid-phrase: "F4 / forwards", "F9 new / session".
